# Documentation site

The docs site for the `@rn-media/*` packages — Docusaurus 3 (React + MDX) with a
custom theme, plus a **fully generated** API reference (TypeDoc → Markdown) that
reads each package's real `index.ts`.

This is the **first pass**: the whole shell, the theme, and both quality gates
proven on one vertical slice (the `@rn-media/player` API in full, the
music-player guide, the position-anchor concept). The remaining packages, guides
and concepts are ported to these templates after review.

## Run

```sh
cd website
npm install
npm start        # dev server at http://localhost:3000, with hot reload
```

`npm start` generates the API reference into `docs/api/` on the fly (via
`docusaurus-plugin-typedoc`), then serves the site.

## Build

```sh
npm run build    # static site into build/, with the API reference generated
npm run serve    # serve the built site locally
```

The build is held to **zero broken links and zero broken anchors** — either one
fails it (`onBrokenLinks: 'throw'` in `docusaurus.config.ts`).

## Add a page

1. Drop an `.mdx` file under `docs/` (e.g. `docs/guides/radio.mdx`) with the
   usual frontmatter (`id`, `title`, `sidebar_position`).
2. Add it to `sidebars.ts` (the API section is autogenerated — no edit needed).
3. Reference the project name only through the shared components —
   `<ProjectName />`, `<Pkg name="player" />`, `<Install packages={[…]} />`,
   `<RepoFile path="…" />`. **Never hardcode the name**; it lives once in
   `src/project.ts` so the pending rename stays a one-file edit.
4. If a code sample needs an identifier the prose introduces (a `service`, a
   `./library` module), add an entry to `AMBIENTS` / `MODULES` /  `PAGES` in
   `scripts/check-mdx-samples.mjs`, typed — never `any`.

## The two gates

Both run in CI and must be green.

```sh
npm run build        # then:
npm run check:api    # every @rn-media/player export is documented or @internal
npm run check:mdx    # every ```ts / ```tsx block on the site typechecks
```

- **`check:api`** (`scripts/check-api-coverage.mjs`, zero deps) diffs the
  generated API pages against `packages/player/src/index.ts`. A public export
  that is neither documented nor marked `@internal` in its TSDoc fails the
  build. It needs the API pages to exist, so run `npm run build` (or `npm start`
  once) first. Reports `documented / internal / total`.
- **`check:mdx`** (`scripts/check-mdx-samples.mjs`, zero deps) extracts every
  `ts` / `tsx` fenced block from `docs/**` and `src/**` `.mdx` files, writes each
  as a standalone module, and runs `tsc` against the packages' `src` with
  `@rn-media/*` mapped there. A ` ```ts fragment ` fence opts a partial out. It
  mirrors the repo's `scripts/check-readme-samples.mjs` exactly. Reports the
  block count.

## Layout

```
docusaurus.config.ts   site config; imports the ONE identity object (src/project.ts)
sidebars.ts            docs sidebar; the API section is autogenerated
src/project.ts         the name / scope / repo — the one file a rebrand touches
src/css/tokens.css     design tokens (palette, type scale) — the one file a restyle touches
src/css/custom.css     maps tokens onto Docusaurus + component styles
src/components/         the shared name components (Project.tsx)
src/theme/MDXComponents.tsx   registers those components globally for MDX
src/pages/index.tsx    the one-screen home
docs/                  hand-written pages (intro, guides, concepts)
docs/api/              GENERATED — do not edit; regenerated on every build
scripts/               the two gate checks
```
